# 컨텍스트 예산 감사 — 이미 깔린 문서 규율을 잰다

**새 프로젝트에 이 방법론을 세팅하는 스킬은 `bootstrap-docs-workflow` 다.** 이 스킬은 반대쪽이다
— *이미 있는* 설치가 실제로 O(1) 인지 재고, 아니면 개보수한다. 오래된 설치는 읽기 프로토콜이
산문으로만 있어 거의 항상 새고 있다.

`bootstrap-docs-workflow/assets/` 에 `session-brief.sh` 와 갱신된 `check-docs-budget.sh` 가
파일로 있다. **재타이핑하지 말고 거기서 복사한다** — 인라인으로 옮겨 적으면 조용히 드리프트한다.

`CLAUDE.md` 가 "이 파일들을 읽어라"라고 지시하면, **세션 시작 비용이 프로젝트 이력 길이에
비례해 커진다.** `session-log` 는 세션마다 쌓이고 `decisions` 는 번호가 늘고 `todo` 는 완료
항목이 남는다. 이 스킬은 그 비용을 **O(1) 로 고정**하는 방법과, 그게 실제로 고정됐는지
검사하는 방법을 담는다.

## 핵심 원칙 — 다섯 줄

1. **캡보다 읽기 범위 고정이 먼저다.** 파일이 커지는 건 문제가 아니다. 매 세션 읽는 양이
   커지는 게 문제다.
2. **읽기 범위를 산문으로 적으면 지켜지지 않는다.** 스크립트가 잘라야 한다. (§1)
3. **총합이 아니라 단위를 재라.** 세션 비용은 파일 크기가 아니라 *읽히는 조각* 하나의 크기다.
4. **자동 로드되는 파일(`CLAUDE.md`)은 읽기 프로토콜로 방어할 수 없다** — 별도로 더 엄격히.
5. **가드는 구조만 본다.** 문장 표현·규칙 내용의 정확성을 검사하면 다듬을 때마다 빨개지고,
   빨간 가드는 결국 무르게 만들어진다.

## §1. 가장 흔한 실패 — 규칙은 맞는데 형태가 틀렸다

이 실패는 거의 항상 이렇게 생겼다. `CLAUDE.md` 에:

```
2. `docs/session-log.md` — **최근 3개 항목만.** 그 위로는 읽지 않는다
3. `docs/decisions.md` — **상단 인덱스 표만.** 필요한 D-번호만 펼쳐 읽는다
4. `docs/todo.md` — **현재 Phase만**
```

규칙은 옳다. 그런데 **자를 줄 번호가 어디에도 없어서** 읽는 쪽은 파일 단위로 읽는다.
실측 사례(2026-08): 규칙대로 11,754자 vs 파일 전체 49,654자 = **4.2배**. 게다가 결정 하나가
늘 때 인덱스는 1줄인데 본문은 ~23줄이 붙으므로 **격차는 계속 벌어진다** — 정책이 막았다고
선언한 O(이력) 증가가 그대로 재현된다.

**고침: 브리핑 스크립트 하나가 범위를 잘라 출력하고, 그 출력이 세션 시작 읽기의 전부가 된다.**
`bootstrap-docs-workflow/assets/session-brief.sh` 를 `scripts/` 로 복사하고 절 구성을 프로젝트
문서에 맞춘다. `CLAUDE.md` 는 파일 목록이 아니라 명령 하나를 가리킨다:

```markdown
## 세션 시작 시 — 읽는 양을 스크립트가 고정한다
**`bash scripts/session-brief.sh` 한 번이 세션 시작 읽기의 전부다.**
**위 파일들을 직접 열지 않는다** — 열면 전체가 딸려 오고 그게 이 규율이 막는 것이다.
필요한 부분은 그때 **범위를 지정해** 펼친다.
```

**"현재 Phase" 같은 판단은 마커로 기계가 읽게 한다.** 진행 중인 `todo` 헤딩에 `★` 를 붙이고
브리핑은 그 절만 출력한다. 사람 판단에 맡기면 결국 파일을 연다. 마커가 없으면 가드가 hard 로
막는다 — 읽기 프로토콜이 깨진 상태이기 때문이다.

## §2. 감사할 때 실제로 재는 법

"토큰 낭비 포인트를 찾아 달라"는 요청에는 **추정하지 말고 잰다.** 산문 진단은 값이 없다.

```bash
# 규칙대로 읽었을 때 vs 파일 전체 — 이 두 수를 나란히 놓는 것이 진단의 전부다
sed -n '1,46p' docs/decisions.md | wc -m ;  wc -m < docs/decisions.md
# 세션 시작에 읽는 조각별 크기
awk '/^## /{if(h)print len" "h; h=$0; len=0; next} h{len++}' docs/session-log.md   # 항목당 줄 수
grep -c '^## D-' docs/decisions.md                                                 # 증가 속도의 분자
wc -c docs/*.md docs/**/*.md | sort -n                                             # 검색 노이즈
```

체크리스트 — 경험상 여기서 나온다:

| 증상 | 신호 | 고침 |
| --- | --- | --- |
| 읽기 범위가 산문뿐 | 규칙에 줄 번호·명령이 없다 | 브리핑 스크립트 (§1) |
| 총합만 재는 가드 | 캡은 초록인데 조각 하나가 비대 | 단위로 재기 (§3) |
| 같은 것을 두 번 읽음 | 진입점 목록 ≈ 로그 최근 N개 | 중복 쪽을 1줄로 |
| 회전 규칙이 없는 디렉터리 | 리포트·산출물이 판마다 쌓임 | 회전 대상에 추가 |
| 영원히 안 걸리는 회전 조건 | "전 항목 완료" 를 기다림 | 남은 항목 이월 후 회전 |
| 문서가 자기 상태를 서술 | "현재 445줄" 인데 693줄 | 숫자를 지운다 |

## §3. 재야 할 것은 파일이 아니라 브리핑이다

캡을 아무리 촘촘히 걸어도 캡은 **파일 크기**를 잰다. 정작 *매 세션 읽는 양*은 아무도 안 잰다.
실측 사례에서 낭비는 **모든 캡이 초록인 상태**에서 일어났다. 브리핑을 도입했다면 그 출력
크기를 가드에 넣는다:

`bootstrap-docs-workflow/assets/check-docs-budget.sh` 에 이 검사가 `BRIEF_SOFT`/`BRIEF_HARD` 로
들어 있다. **가드를 통째로 그 파일로 교체하는 게 가장 안전하다** — 거기엔 이 검사 말고도 단위
검사·bash 3.2 회피·`grep -c` 함정 보정이 함께 들어 있고, 인라인으로 옮겨 적으면 드리프트한다.

**그 숫자를 문서에 적지 말 것.** "브리핑은 9.8k자로 고정된다" 같은 문장은 다음 달에 거짓이
된다 — 어느 참조 문서가 "현재 445줄" 이라 적힌 채 693줄이 돼 있던 것과 같은 실패다.
문서는 *어디서 재는지*를 가리키고, 숫자는 가드가 갖는다.

## §4. 총합이 아니라 단위를 재라

가장 흔한 가드 버그다. `session-log` 총 줄 수와 항목 개수가 초록인데 항목
하나가 36줄이면 브리핑의 절반을 그게 먹는다. **세션 시작에 읽히는 조각의 크기**를 재라:

- `session-log` → 항목당 본문 줄 수 (soft 15 · hard 22)
- `decisions` → 결정당 본문 줄 수 (soft 20 · hard 30). 총합 상한은 결정 수에서 **유도**한다
  — 결정이 늘었다는 이유로 빨개지는 가드는 무르게 만들어진다.
- `current-task` → 전문 줄 수 + 진입점 개수

**항목 경계를 셀 때 파일 꼬리말을 본문으로 세지 말 것.** 빈 줄·`---`·`> 이전 이력` 인용은
빼야 한다. 안 그러면 마지막 항목에 4줄이 덤으로 붙는다(실제로 겪은 오탐).

## §5. 회전(rotate)은 삭제가 아니다

`docs/archive/` 로 옮기고 원본 자리엔 한 줄 포인터를 남긴다. git 에 남아 검색·복구된다.

- **session-log** — 최근 N개만 남기고 `archive/session-log-YYYY-MM.md` 로. 원본 하단에
  `> 이전 이력: ...` 한 줄. (이 포인터를 빠뜨리는 일이 잦다.)
- **todo** — **먼저 남은 미완 항목을 갈 Phase 로 이월**시키고(`(3주차에서 이월)` 처럼 출처를
  적는다) 그 다음 회전한다. "전 항목 `[x]`" 를 기다리면 미완 하나 때문에 영원히 회전하지
  않는다. 회전 후 `★` 마커를 옮긴다.
- **리포트·발표본** — 개정마다 새 날짜 파일이 되는 종류는 **현행판 하나만** 두고 이전 판은
  생성물(`.pptx`/`.docx` 등)까지 함께 회전한다. 세션 시작에 안 읽어도 `grep -r docs/` 가
  매번 n중으로 걸린다. 아카이브된 판은 *그때의 기록*이므로 오늘의 값과 대조하는 테스트
  목록에서도 뺀다.
- **decisions 는 회전하지 않는다 — 압축한다.** 결정은 지금 코드가 왜 이런지의 유일한 근거다.
  밀어내면 다음 세션이 같은 논쟁을 반복한다. 번호는 재사용하지 않고, 뒤집힌 결정은 지우지
  않고 상태만 `폐기(→D-0NN)` 로 바꾼다.

## §6. 자동 로드 파일은 따로 방어한다

`CLAUDE.md` 는 읽기 프로토콜로 못 막는 유일한 파일이다. 크기 외에 **구조**까지 검사한다:

- **상한 계약** — 문서 안에 상한을 한 줄로 선언하고 가드가 그 줄을 파싱해 자기 상수와 대조.
  한 곳만 고치면 불일치로 막히므로 "일단 늘리고 보자"가 안 된다.
- **줄 수만으로는 부족하다** — 전체 문자 수 · 전체 줄 수 · **한 줄 길이** · **섹션 본문 줄 수**
  넷을 함께 본다. 표 행 하나에 요약을 밀어넣는 게 실제 비대화 경로다.
- **허용 섹션 목록을 별도 파일로** — 섹션 추가에 두 파일 수정을 요구해 스프롤을 막는다.
- **백틱 경로 존재 검사** · **참조 번호 해결 검사** — 위치 인덱스가 틀린 허브는 없는 것보다
  나쁘다. 다음 세션이 그걸 믿고 헤맨다.

## 적용 순서

1. **잰다** (§2). 규칙대로 vs 파일 전체 두 수를 뽑는다.
2. `bootstrap-docs-workflow/assets/` 에서 `session-brief.sh` 와 `check-docs-budget.sh` 를
   `scripts/` 로 복사하고 파일명·절 구성을 맞춘다. 실행해 출력 크기를 확인한다.
3. `CLAUDE.md` 의 세션 시작 절을 그 명령 하나로 교체한다. 허용 섹션 목록도 같이 고친다.
4. `todo.md` 의 진행 중인 Phase 헤딩에 `★` 를 붙인다. 새 검사가 **실제로 발동하는지** 확인한다
   — 마커를 떼 보고 hard 로 막히는지, 로그 항목 하나를 40줄로 불려 보고 총 줄 수는 초록인
   채로 잡히는지. 통과만 하는 검사는 커버리지처럼 보여서 없는 것보다 나쁘다.
5. 걸린 위반을 고친다(회전·압축·이월). **가드를 초록으로 만들고 끝낸다** — soft 경고를
   방치하면 다음 사람이 상한을 무르게 만든다.
6. 결정으로 남긴다. 무엇을 왜 바꿨는지, 그리고 **버린 안**도.

## 이식성

가드·브리핑은 **bash 3.2 에서 돌아야 한다** (macOS 기본 `/bin/bash`). `mapfile`/`readarray`/
`declare -A` 는 bash 4 전용이라 쓰지 않는다 — `set -u` 와 겹쳐 검사가 통째로 건너뛰어지는데
**종료코드는 0** 인, 통과처럼 보이는 실패가 된다. 배열 대신 개행 구분 문자열 + `while read`.

`$(grep -c ... || echo 0)` 도 쓰지 않는다. 매치 0건일 때 grep 은 "0" 을 출력하고 종료코드 1 을
반환해 `|| echo 0` 이 함께 발동, `"0\n0"` 이 되고 이후 비교가 죽으면서 검사가 조용히
건너뛰어진다. **대입한 뒤 실패만 보정한다.**
