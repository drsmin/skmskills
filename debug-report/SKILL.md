# debug-report — 원인부터 찾고, 보고하고, 고친다

에러만 붙여 넣은 요청은 두 가지로 비싸진다. 모델이 맥락을 추측하며 파일을 이리저리 열어 대화가
불어나고, 엉뚱한 곳을 고쳐 되돌리는 왕복이 생긴다. 이 스킬은 **맥락은 싸게 스스로 채우고, 못 채운
것만 묻고, 고치기 전에 원인을 한 번 보고**하게 해서 둘 다 줄인다.

## 1. 맥락 채우기 — 묻기 전에 먼저 본다 (명령 4개 안쪽)

사용자가 준 것과 아래 표를 맞춰 보고, 빈 칸만 스스로 채운다.

| 칸 | 스스로 채우는 법 |
| --- | --- |
| 하던 일 | `docs/current-task.md` 의 ★현재★ 줄(있으면 `head -40`) · 없으면 `STATUS.md` 진행 중 |
| 바뀐 것 | `git status -s` · `git diff --stat` · `git log --oneline -3` |
| 어떤 명령에서 | 로그 첫머리·프롬프트 줄. 안 보이면 `scripts/check.sh` 가 있으면 그것 |
| 기대 / 실제 | 로그의 마지막 오류 줄이 "실제". "기대"는 보통 "통과" |
| 이미 해 본 것 | 대화에 없으면 비워 둔다 (같은 시도를 반복하지 않도록 2단계 뒤에 한 번 묻는다) |

- 파일은 **범위로** 연다(스택의 줄 ±30). 로그·출력은 **꼬리만**(`| tail -40`). 통째로 열지 않는다.
- 그래도 판단이 갈리는 빈 칸이 있으면 **한 번에, 두 개까지만** 묻는다. 막히지 않는 빈 칸은 묻지
  않고 가정을 한 줄 적고 진행한다.

## 2. 재현 — 한 번

- 실패한 명령을 **한 번** 다시 돌려 같은 오류인지 본다(`2>&1 | tail -40`). 재현이 안 되면 그 사실이
  곧 단서다(캐시·순서·환경) — 바로 보고한다.
- 서버를 바꾸는 명령(homelab 의 `ssh pve` 쓰기, 배포, DB 변경)은 **돌리지 않는다**. 읽기 전용 확인만,
  나머지는 사용자에게 명령을 건넨다(저장소 `CLAUDE.md` 가 우선).

## 3. 좁히기 — 가설 세 개까지

- 가설을 **최대 3개**, 각각 근거 한 줄(로그 줄 · `file:line` · 방금 바뀐 파일)과 함께 세운다.
- 가장 싼 확인부터 하나씩 깬다. 확인할 때마다 가설 목록을 갱신하고, 새 가설을 무한히 늘리지 않는다.
- 브라우저 화면·포커스·네이티브 위젯 문제는 jsdom 테스트 통과만으로 닫지 않는다 — 실제 브라우저(헤드리스
  포함)로 다시 본다.

## 4. 원인 보고 — 고치기 전에 (이 형식, 8줄 안쪽)

```
원인: <한 문장>
근거: <file:line 또는 로그 줄 1~2개>
고칠 방법:
  1. <가장 작은 수정> — 바뀌는 파일 <N>개
  2. <대안이 있으면>
영향: <같이 깨질 수 있는 곳 / 없음>
확인: <고친 뒤 돌릴 명령>
```

- 번호를 붙여서 사용자가 "1번만", "2번으로, X는 건드리지 마"로 답할 수 있게 한다.
- **언제 바로 고치나:** 사용자가 처음부터 "고쳐줘"라고 했고, 수정이 한 파일·몇 줄이며 되돌리기 쉬우면
  보고 없이 고치고 이 형식으로 *결과*를 보고한다. 그 밖(여러 파일 · 설계 판단 · 포맷/스키마 · 외부 연동 ·
  테스트를 끄거나 고쳐서 통과시키는 경우)은 보고하고 기다린다.
- 원인을 못 찾았으면 지어내지 않는다. "확인한 것 / 배제한 가설 / 다음에 볼 곳"으로 보고한다.

## 5. 고친 뒤

- 4단계의 "확인" 명령을 **같은 그대로** 다시 돌린다. 통과면 한 줄, 실패면 꼬리 전문.
- 테스트를 skip·삭제하거나 기대값을 실패에 맞춰 고쳐서 초록을 만들지 않는다.
- 커밋·기록은 이 스킬이 하지 않는다 — 마감은 `wrap-up-docs-commit`. 재발 방지 교훈이 있으면 그때
  session-log 한 줄로 남기라고 보고 끝에 적는다.

## 멈추는 지점

- **같은 오류로 세 번 고쳐도 안 되면 멈춘다.** 지금까지 시도한 것·배제한 가설·남은 가설을 5줄로
  정리하고, 새 세션(또는 새 스레드)에서 그 정리로 다시 시작하자고 권한다. 긴 실패 이력이 쌓인 대화는
  이후 판단을 흐리고 매 턴 비용도 키운다.
- 원인이 이 저장소 밖(의존성 버그 · 외부 서비스 장애 · 사용자 환경)이면 그 근거와 우회책만 보고한다.

## 사용자가 처음부터 맥락을 줄 때

사용자가 아래 순서로 주면 1단계를 거의 건너뛴다. 사용자가 템플릿을 물으면 이걸 건넨다:

```
[요청] <원인만 / 고쳐줘>
[하던 일] <한 줄>
[바뀐 것] <방금 바꾼 파일·설정>
[해 본 것] <이미 시도한 것>
(로그는 맨 아래에. 길면 끝에 질문을 한 줄 더)
```
